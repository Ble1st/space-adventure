# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Mobile-first 2.5D space game (inspired by Interstellar Pilot 2) with a fully autonomous economy and factions that run without player input. The world is a graph of sectors; each sector is its own instance and the only way between them is via jumpgates. Stack: engine-independent C# core + Godot 4.7.2 (.NET build) as the view. The user communicates in German.

**Architecture is the top priority.** Features must be added as separate modules/systems behind clear seams (registration, interfaces, events, data files), not by growing central classes. Keep `SpaceSim.Core` free of Godot and file IO.

## Commands

The .NET 10 SDK is installed; `SpaceSim.Core` targets `net8.0`, the test and tool projects `net10.0`, the Godot project `net9.0` (the Godot 4.7 Android template only accepts net9.0 for C#).

```
dotnet build                       # solution (Core, tests, balance tool; NOT the Godot project)
dotnet test                        # all unit tests (~5 s, includes long deterministic runs)
dotnet test --filter "FullyQualifiedName~Economy_RunsStably_WithoutPlayer"   # single test
dotnet run --project tools/SpaceSim.Balance -- --ticks 60000 --every 5000    # headless economy report (also: --seed N --world file.json --csv out.csv); exit code 1 if prices degenerate

dotnet build godot                 # build the Godot C# project
godot-mono --path godot            # run the game (use godot-mono, NOT godot: plain godot cannot run C#)
godot-mono --path godot -e         # open the editor
godot-mono --headless --path godot --fixed-fps 60 -- --selftest   # scripted headless run: autopilot across sectors, docking, panels, save/load; prints SELFTEST OK, uses its own save file
```

`godot-mono` is a symlink in `~/.local/bin` to `~/.local/opt/godot-mono/`. Godot prints harmless "Leaked unsafe reference"/ObjectDB warnings when quitting from code.

## Core architecture (`src/SpaceSim.Core`)

**Two layers.** Simulation layer: every sector exists as plain data in `Universe` and is always simulated. Presentation layer: only `Universe.PlayerSector` is materialized as a Godot scene. Core must never reference Godot; the view must not invent simulation state.

**Modules and systems.** `SimulationRunner` builds its system list from `ISimModule`s (`Modules/DefaultModules.cs`: Production, Jobs (Phase 6), Resources, Trade, Upgrades (Phase 7), Construction (Phase 8), Lifecycle) via `SimulationBuilder.Add(system, interval)`. Order matters (production/market before AI, lifecycle last). A system with `interval > 1` runs every n ticks and receives `dt = n` (simulation LOD) — it must scale by `dt`. To add behavior: write an `ISimSystem`, register it in a module (or a new module in `DefaultModules()`).

**Events.** `Universe.Events` (`SimEvents`) is a synchronous bus (`TradeCompleted`, `MineDelivered`, `StationBuilt/Removed`, `ShipSpawned/Removed`). Stats, UI toasts etc. subscribe; systems publish. The bus is not persisted — re-subscribe after loading (the view does this in `Main.AttachSession`).

**Content is data-driven.** `Content/default-world.json` (embedded resource) defines goods (25 JSON goods: six raw ores, refined goods, components, end goods, the kit tiers `ship_kit_light` (id 22, formerly `ship_kit`) / `ship_kit_medium` / `ship_kit_heavy`, `propellant`; referenced by string key `Good.Key`, `GoodId` = index+1, with a UI `color`; since Phase 5a every module additionally gets an automatic good appended behind them, see the Phase 5a section), asteroid classes (ore mixes), station types with recipes (22, incl. the three module factories), factions, sectors, gates, stations, belts (fields), ships. Ore chain: 6 ores (iron, ice, copper, silicon, titanium, platinum) → refined (steel, water, hydrogen, copper, wafers, titanium, platinum, energy) → components (electronics, hull plates, fuel cells, life support) → end goods (food, consumer goods, luxury goods, ship kit). `DemoUniverse` has `GoodId` constants for the default world; `ContentTests` guards them and the chain's consistency. `WorldBuilder.Parse/Build` validates and throws `WorldFormatException` with the offending name — including the slot sections: duplicate keys, unknown slot type/size/class/module keys, unknown goods in a module's `cost`, unknown `grants` names, module larger than its slot, module slot type mismatch, fit length ≠ slot count, empty required slot, and the power balance (Σ powerOutput ≥ Σ powerDraw; Σ peakDraw − (powerOutput − powerDraw) ≤ Σ powerStorage). `DemoUniverse.Create()` is just `WorldBuilder.BuildDefault()`. Core never reads files; callers pass JSON text. The file also has optional `slotTypes`/`modules`/`shipClasses`/`shipModels` sections (missing sections = empty registries on `Universe.SlotTypes/Modules/ShipClasses/ShipModels`) and `goods[].form` (`solid` default, `liquid`; content only, not persisted, old saves stay v3-loadable). `goods` carry `Good.Form`; `Model/ShipStats.Compute(class, fit)` derives power/cargo/hull/mass/thrust/speed (clamped to `ShipStats.MaxSpeed`)/upkeep/capabilities/laser tier as a pure function. Phase 3a added all of this as data only; Phase 3b wires it up: every ship carries `ModelKey` ("" = no model, legacy ships keep the old flat values), its `Slots` list (default: the model's class slots) and its `Fit` (module key per slot, null = empty), plus the derived `Ship.Stats` — `Ship.RecomputeStats(u)` recomputes after Fit/Slots changes and on load (without a resolvable model the fallback is hull 100). `Ship.MaxHull` is now an instance property from `Stats.Hull` (the const is gone; the view uses `ship.MaxHull`); `CargoCapacity` stays a field for its many consumers but is set from `Stats.Cargo` at creation/load when a model exists; capabilities come from `Stats.Capabilities` unless explicitly set (`CapabilitiesSet` semantics unchanged, a saved value wins over the model). `Travel.Plan/Start/Estimate/Ticks` take an optional ship and use `Travel.SpeedOf(ship)` = `Stats.Speed` when a model is present, else the `ShipSpeed` constant — all unit models are 8, so travel is unchanged. World JSON: `ships[]` groups and `player` accept an optional `model`; if absent, `WorldBuilder.NewShip` picks the unit model by role+cargo (`UnitModelFor`: trader/100→`unit_trader_100`, trader/60→`unit_trader_60`, miner/100→`unit_miner_100`, miner/60→`unit_miner_60`, player→`unit_player`, else "" e.g. Fighter); an unknown explicit key throws `WorldFormatException`. `FleetSystem.Expand` copies model/slots/fit from the parent ship. Save v4: `ShipSave` gains `ModelKey`, `Slots`, `Fit`, and the four slot-content sections (`SlotTypes`/`Modules`/`ShipClasses`/`ShipModels`) are persisted in the save like the other content (goods, asteroid classes, station types incl. recipes), so a save is self-contained; `MigrateV3ToV4` sets only `ModelKey` per role/cargo and injects the embedded default-world slot registry (v3 saves contain no slot content), and on load `Slots`/`Fit` are filled from the model when the save lacks them; `UniverseHash` additionally hashes `ModelKey` and `Fit`. The unit models reproduce the old flat values exactly (cargo 100/60, hull 100, speed 8, role-derived capabilities), so behavior, `UniverseHash` roundtrips and the balance run are unchanged apart from the hash value. Tuning knobs live in `EconomyRules` (JSON `rules` section, also saved).

**Space and travel.** Entities reference each other by typed ID structs in dictionaries on `Universe`. Jumpgates are the edges of the sector graph (`Universe.FindRoute`, per-tick cached via `CachedRoute`/`IsReachable`; `Gate.Open=false` blocks). Ships outside the player's sector have no physics: `Travel.Plan` turns a trip into contiguous `Leg`s (one per sector, detouring around obstacles via `PathPlanner`), `Transit` stores them, `ArrivalTick` is the last leg's end. `Travel.Start` consumes real fuel from the ship's tank (Phase 4b; see the Phase 4 sections at the end). `Travel.Estimate` is the cheap (straight-line) variant for AI scoring. Obstacles (`Obstacle`, built by `Universe.GetObstacles`) are asteroids (`Asteroid.ToObstacle()`, generated by `Demo/AsteroidGenerator`) and station bodies. Ships target `Station.DockPoint(shipId)` / `ResourceField.WorkPoint(shipId)`, never centers. `Ship.Position`/`Sector` are only updated on arrival; mid-trip location comes from the legs.

**Ship index.** `Universe.Tracker` (`ShipTracker`) maps sector → parked ships / ships with a leg in that sector. Always mutate ship placement through `Universe.AddShip/RemoveShip/StartTransit/FinishTransit/MoveShip`, never by writing `Ship.Sector`/`Transit` directly. `Materializer.Snapshot(u, sector, fractionalTick)` uses the index to derive where each NPC ship is (moving ships by interpolating the active leg, parked ones at `Ship.Position`); the view renders that.

**Capabilities and controller (Phase 2).** `ShipRole` is still the stored current-task label (save format, display), but systems decide by capability, not by role: `Ship.Capabilities` (`[Flags] Capability`: `Cargo`, `Mining`, `Combat`, `Construction`, `Salvage`, plus `Jump`/`Stealth` which exist but are unused until the deferred jump-drive/cloak modules, no `Research`) and `Ship.Controller` (`Ai`/`Player`, checked via `Ship.IsPlayer`). Both are saved (`ShipSave.Capabilities` int / `Controller` string, nullable, so the format stays v3; old saves without them derive from the role) and part of `UniverseHash`. `CapabilityDefaults.ForRole/ControllerFor` derive them from the role at the creation points (`WorldBuilder.NewShip`, `UniverseSerializer.FromSave` for old saves, `FleetSystem.Expand`) and in `Universe.AddShip` only when the creator never set them (`Ship.CapabilitiesSet/ControllerSet` flags, set by the property setters), so an explicit `Capability.None` is a valid value. Ships with a resolvable model (Phase 3) always take `Capabilities` from their fit (`Ship.RecomputeStats`), so removing a module takes effect even after load; the saved value only counts for model-less ships. `TraderSystem`/`MinerSystem` keep the role as the task filter and additionally require `Has(Capability.Cargo)`/`Has(Capability.Mining)`; a ship that lacks it is released via `JobRelease.Release` (order and reservation dropped, a running transit is flown to its end and finished without trading/mining, cargo stays) instead of being skipped — skipping froze such ships mid-transit with a ghost reservation; `FleetSystem`, `UpkeepSystem`, `EconomyStats` and `StationLifecycleSystem` count economically active AI ships via `Ship.IsEconomyAi` (Controller Ai with Cargo or Mining); `TradeActions` (PlayerSold/PlayerBought) recognize the player via `IsPlayer`; `Materializer` skips only the active ship (`Universe.PlayerShip`), so parked own ships are rendered (Phase 5c). Pure display (ship colors in SectorView/SectorScreen, `ShipSnapshot.Role`) may still use the role.

**Economy.** Price per station and good = `BasePrice * clamp(Target / max(Amount,1), 0.25, 4)` (`MarketSystem`). `ProductionSystem` runs station recipes. `TraderSystem` scores routes by profit per tick (margin × units / `Travel.Estimate`) with stock reservations by other traders; stations only pay what they have (`TraderSystem.CanAfford`, unpaid cargo is dumped); since Phase 5a a trader buys at most what the selling target still accepts (`Station.AcceptableUnits`), so nothing is dumped above the overstock cap. `MinerSystem` mines belts and refuses to mine when the mix is worth less than `MinPriceFactor` × its base value. Prices: besides the stock price, a factory bids at most `InputWillingness` of its products' value for inputs (`MarketSystem`, stops price spikes from bankrupting processors; with several recipes using the same input the highest of their ceilings counts, Phase 5a); stations accept only up to `Target × OverstockFactor` (`Station.AcceptableUnits`) and production pauses when outputs exceed that (`ProductionSystem`). Money flow (`UpkeepSystem`): station income (faucet) and upkeep, wealth taxes, ship upkeep, fuel, ship/station purchases (sinks); without sinks credits pile up at ships. `StationLifecycleSystem`: bankrupt stations are removed unless `BankruptcyProtected` (formerly `Essential`), derived `Critical` (last reachable producer of a good) or a build site (`Universe.RemoveStation` cancels referencing orders), scarce goods (avg price > `BuildPriceRatio`) trigger a new producer funded by the richest station *or ship* (investors) — since Phase 8 as a build site that needs materials and a construction ship (see the Phase 8 section), direct build only as fallback. `FleetSystem`: rich ships buy ships up to `MaxTraders/MaxMiners`, counted as capacity units since Phase 6 (see the Phase 6 section: cargo ÷ 100 for trade, laser tier for mining; the AI chooses the model) — but a new ship needs a **ship kit** of its class's tier (`FleetSystem.KitKeyFor`: `ShipClass.Kit`, fallback `EconomyRules.ShipKitGoodKey` = `ship_kit_light`; made by shipyards from hull plates, electronics and fuel cells, i.e. from titanium/platinum chains) from a reachable yard, which receives `NewShipCost`; the ship appears at the yard. Idle broke ships are abandoned (player money is never involved: these systems only touch economy-AI ships, which are their own wallet); idle ships back off their re-planning (`TraderSystem.IdleBackoff`). Scarcity/glut for station construction is measured on stock ratios, not prices, and only goods some station type can answer count (a producer type for scarcity, a recipe consumer type for glut; Phase 5a — otherwise module goods on stock without any consumer would block every consumer build). Idle AI ships only re-think every ~10 ticks (`Ship.NextThinkTick`).

**Determinism.** All randomness goes through `Universe.Rng` (`DeterministicRng`, state saved). `Diagnostics/UniverseHash` hashes simulation state; tests assert same seed → same hash and save → load → continue is bit-identical. Never use `System.Random`/time/hash-order-dependent iteration inside systems.

**Persistence.** `Persistence/SaveGame` DTOs (versioned, currently v11 — v9 Phase 6 multirole, v10 Phase 7 quality/upgrades, v11 Phase 8 construction/breaker/warehouse, see the phase sections; `MigrateV1ToV2` converts the old field-owned ore into asteroid ore, `MigrateV2ToV3` the single-ore fields/asteroids into `legacy_<good>` classes (mine orders now reference a field index), `MigrateV3ToV4` assigns ships their `ModelKey` (unit model by role/cargo) and injects the default-world slot content, `MigrateV4ToV5` fuel + refineries, `MigrateV5ToV6` module goods/factories/kit tiers (Phase 5a), `MigrateV6ToV7` moves the player ship's credits into the player wallet (Phase 5b), `MigrateV7ToV8` adds outfitter/ship-dealer content, the trade station and the skiff models (Phase 5c), `Migrate` hook in `SaveGameJson`) are separate from the runtime model; `UniverseSerializer` converts both ways (slot content sections included, `Ship.RecomputeStats` after loading); derived state (Events, Tracker, caches) is rebuilt. When adding persistent state to `Universe`/`Ship`/`Station`, update DTOs + serializer + `UniverseHash` and bump `SaveGame.CurrentVersion` with a migration if the format breaks. `OfflineCatchUp` replays missed time (capped at 10k ticks, `SimClock` = 4 ticks/s; ~0.3 ms/tick on desktop).

**Navigation/avoidance/collision.** `Navigator.Next` gives the player autopilot the next waypoint (route gates + `PathPlanner`). `Collision.Resolve` (circles) is applied to the player in the view (`PlayerShip`): hard impacts on asteroids/stations (> `HardImpact`) damage the hull unless the ship is in `Grace` (after undock/respawn/jump); NPC ships only push softly and never damage; a lateral-damping flight assist and braking keep the ship from drifting into obstacles, and the autopilots slow down near obstacles (`Main.ClearanceScale`). Docking makes the ship fly into the station, become invisible and collision-free, and repairs the hull; undocking reverses it; `Avoidance.Desired` is a purely cosmetic sidestep between NPCs/player in the view. Neither feeds back into the simulation, so two NPC fleets may still cross in the data model. `PathPlanner` recursion is bounded by `MaxDepth` and a `MaxExpansions` node budget. Keep asteroid sizes in the view equal to `Obstacle.Radius`.

**Asteroids, ore and respawn.** `Asteroid` (Model/Asteroid.cs) carries its own finite ore (`Ore`/`MaxOre`) and a `ClassKey`; `AsteroidClass` (content) defines a weighted ore mix (`Yields`), `ChunkChance` per shot and `OreFactor` (richness). Ore type is rolled **per chunk**, not per asteroid. Asteroids shrink while mined (`Radius` depends on remaining ore) and are removed at 0 (`AsteroidDepleted`). Ore-bearing asteroids belong to the belt of the nearest `ResourceField` with the same class (`Sector.FieldFor`, `MiningRules.BeltRadius`); background rocks have no class/ore and are just obstacles. A field is only a belt descriptor (`ClassKey`, `Position`, `TargetAsteroids`, `RespawnTicks`); its ore is the sum of its asteroids (`Belt.OreIn`). `AsteroidRespawnSystem` (ResourceModule, interval 10) regrows missing belt asteroids with random ore, deterministically via `Universe.Rng`, never within 45 units of the player ship. Placement rules are shared by world generation and respawn (`BeltPlacement`).

**Player mining.** `Mining/OreChunks` is a real-time, non-persisted micro-simulation for the player's sector: the laser is fired **one shot at a time** (`TryFire`; a trigger that arrives during the reload time `ShotInterval` returns `Cooldown`, holding does nothing — the automatic mode simply re-triggers every frame). Every shot goes through the shared rule `Mining/LaserShot.Roll`: with the asteroid class's `ChunkChance` it releases a chunk of a random ore type (class weights) whose size is random (`MiningRules.ChunkTable`, small common, large rare), capped by the asteroid's ore. Each shot also gives the shooter a **recoil** impulse (`RecoilImpulse`, away from the asteroid): real velocity change for the player (`Main.OnShot`), a decaying visual kick for NPC markers (`SectorView.Kick`) because NPC positions are simulation data. The ore leaves the asteroid when the chunk is released; the tractor beam (`Update`) pulls chunks in and loads them (partially if the cargo is nearly full); uncollected chunks expire and their ore is lost. `Mining/MiningAutopilot` is the automatic mode (seek asteroid → approach → fire + tractor → when full go to the best buyer, dock, sell → repeat; other sector if this one is empty); it only returns a `MiningStep` (what the view should do), so it is tested with a kinematic harness in `MiningTests`. `Trading/TradeActions.SellAll/Quote/BestBuyer` implement selling with the same payout rules as NPC trade. NPC miners fire the same shots inside the simulation (`ShotTimer` reload, `u.Rng`, max one shot per tick, ore taken from the asteroid into cargo, `MinerShot` event per shot). A `MineOrder` names a belt (`Field` index) and a destination station; since chunks are mixed, the miner scores stations by the expected value of the mix (`MixValue`), sells what the station accepts via `TradeActions.SellAll` and drives leftovers to the next best buyer (or dumps them); fields with other miners are penalised (`CrowdPenalty`, herd protection). The view draws NPC lasers/flying chunks/recoil only from those `MinerShot` events when they happen in the player's sector, so what you see is exactly what the simulation did. Expected NPC yield: `MiningRules.ExpectedOrePerSecond`.

**Diagnostics.** `EconomyStats.Snapshot` and `RouteRecorder` (event-based) feed the in-game economy panel and `tools/SpaceSim.Balance`. Use the balance tool after any economy change: it caught money explosions and herding that unit tests missed.

## Godot project (`godot/`)

`godot/SpaceAdventure.csproj` (Godot.NET.Sdk/4.7.2) references the Core and is deliberately **not** in `SpaceSim.slnx`. `scripts/Main.cs` is only the composition root (wiring, steering priority throttle slider/turn buttons > pointer > autopilot, gate jumps, docking). Components: `Game/GameSession` (universe + fixed-step simulation), `Game/SaveService` (user:// file, atomic write; `UseFile` for tests), `World/SectorView` (builds sector from Core data, renders NPC ships), `World/PlayerShip` (flight model, collision), `World/MiningView` (laser, tractor, chunks, target ring, NPC mining visuals), `World/Fx`/`Sfx` (particles; procedurally generated audio, no asset files), `Ui/Hud` (composition root) + `Ui/Kit/` (reusable building blocks: `UiKit` palette, `KitButton` with states, `KitWindow`, `KitBar`, `KitSlider`, `IScreen`/`ScreenRegistry`) + `Ui/Screens/` (`FlightHud` flight HUD, `CommandMenu` hamburger menu, dock screens, and the command center of UI.md section 4: `CommandCenter.cs` base — full-screen with left rail (`CommandAreas`), content right, "← Flight" bottom left — plus one class per area: `UniverseScreen` (sector map from Core data, switchable layers faction/ships/prices/security, route via `Universe.FindRoute`, "plan route/autopilot" sets the Main autopilot target), `SectorScreen` (top-down sector view: stations, belts, gates, NPC ships via `Materializer`, player), `FactionsScreen`, `MyFactionScreen`, `FleetScreen` (only the auto-mining toggle has a real effect), `AssetsScreen` (tabs + ship detail window, "switch to this ship" disabled: "Bereits aktiv", else a hint to switch in the hangar of the station where the ship is parked), `CommsScreen` (placeholder inbox/negotiation, counter badge on the hamburger menu), `SystemScreen` (save/load/new game with start-package chooser, Phase 5c)) + `Ui/Panels` (map, economy debug, dock) + `UiPlaceholders.cs` (the single place for invented display values: shield, power, security, taxi price, comms messages, faction personality, fleet command grid — dimmed and labelled, never saved), `Ui/TouchButton` (multi-touch aware; `Ui/Pointer` unifies mouse and touch — on touch devices only touch events are handled). Plain primitive meshes are used; there are no art assets yet. Autosave every 30 s and on pause/close. `SectorView.SyncAsteroids` mirrors the Core asteroid list every frame (growing on respawn, shrinking while mined, bursting when depleted). The `--selftest` asserts zero hard collisions during autopilot, auto-mining and selling, plus slider behavior (50 % accelerates, reverse capped at 20 %) and the weapon button (reloading after a shot); it also opens and refreshes every command-center area without exception, checks that the universe sector selection yields the hop count matching `Universe.FindRoute`, that "plan route" sets an autopilot target and that "← Flight" closes everything; and checks the orbit camera (default view == old fixed offset (0,38,24), rotated camera still looks at the ship at the set distance, screen→world roundtrip of the ship center with a rotated camera, the menu action "cam_reset" resets, swipes steer nothing, invert/zoom/target-lock menu actions work). `--ui-shots <dir>` (not headless, needs DISPLAY) loads a demo world and saves review PNGs (flight HUD, HUD with rotated camera, hamburger menu, dock areas, command-center areas) via `RenderingServer.FramePostDraw` + `Viewport.GetTexture().GetImage().SavePng()`. The pure Core display functions for the command center live in `SpaceSim.Core/Trading/SectorEconomy.cs` (`PriceLevel` per sector, `TotalValue` = the ship's own credits + cargo at base prices — a player ship has no own credits since Phase 5b —, `PlayerNetWorth` = player wallet + value of all player ships) with unit tests. All player-money displays (HUD, dock screens, command center, selftest) read `Universe.WalletOf(ship)` / `Universe.PlayerWallet`, never `Ship.Credits`.

Space plane is XZ (`Vec2.Y` → world Z), tilted perspective camera for 2.5D. Controls (UI.md section 2): ◀ ▶ turn buttons bottom left (hold to turn, keys A/D or arrows), horizontal throttle slider bottom right from STOPP to MAX (forward only; it stays until changed, key W/up raises it, X = STOPP) and a separate hold button "RÜCK" between the turn buttons and the slider (80×56 px, half the old edges but the 56 px minimum touch target) for reverse (max 20 % of max speed, takes precedence over the slider; keys S/down; pure mapping in `SpaceSim.Core/Flight/Throttle.cs`). Camera: freely orbitable around the ship and always aimed at it — pure Core math in `SpaceSim.Core/Flight/OrbitCamera.cs` (yaw full 360°, pitch clamped 15–85° above the plane, distance clamped, `Reset`, soft `Follow`; the default view equals the old fixed offset (0, 38, 24)) with unit tests; Godot only applies `cam.Position = ship + Follow(offset)` + `LookAt(ship)`. Input: touch/mouse never steers the ship. One finger or left-mouse drag orbits ("grab the world": swiping right moves the camera left; `OrbitCamera.InvertDrag` flips it), a short tap (< 14 px, < 0.45 s) selects a target; two fingers pinch-zoom; right/middle mouse drag also orbits, wheel zooms. The hamburger menu (`CommandMenu`, bottom left) holds the camera settings: zoom −/+, free camera or **target lock** (`CameraMode.TargetLock`: `OrbitCamera.FollowTarget` rotates the yaw so the selected asteroid, else the autopilot target in the same sector, lies ahead of the ship; horizontal drag then has no effect), invert drag, reset. The "Kommando" button top right (next to map/time, shows the comms counter) opens the command center. The camera setting is not saved in the save game and is kept across docking/undocking and jumps; while docked/menus/full-screen screens are open, camera gestures are ignored (input belongs to the UI). Everything screen↔world (picking stations/gates/asteroids, hold-to-fly pointer, target marker, firing-arc cones) is computed with the rotated camera (`UnprojectPosition`/ray-plane); the arc overlay draws around the projected ship nose. Godot's Y rotation is counter-clockwise, so turning right *decreases* `PlayerShip.Heading` (`PlayerShip.HeadingChange`, guarded by a selftest check); touch/mouse never steers the ship: one finger or left mouse drag orbits the camera, a short tap selects a target (station/gate/asteroid). Priority: slider/buttons > pointer > autopilot; manual input cancels autopilot and auto-mining. Weapon bays on the right edge, one button per bay (laser, tractor): state (ready/outside arc with turn hint/reloading bar/no target) is the pure Core function `SpaceSim.Core/Weapons/FiringArc.cs` over `WeaponBay` data (facing/arc/range; the mining laser is a 360° turret so gameplay is unchanged), the firing arcs are drawn as cones around the ship, "Alle Feuer" fires only ready in-arc weapons. Top bar: hull, fuel and credits real, shield/power placeholders, sector chip, map and time-lapse buttons, target card with autopilot/auto-mining switches and the context button ("Andocken" near a station, "Springen" at a gate). Mining: tap an asteroid to select it, the laser bay button (key F) fires once per shot (green when reloaded, grey with bar while reloading), the tractor bay (key G) toggles the tractor beam, "Auto-Mining" (key M) runs the automatic mode; slider/turn input cancels it. Docking opens the dock menu and full-screen dock areas (UI.md section 3, `godot/scripts/Ui/Screens/`: `DockMenu`, `DockAreaScreen` + `TradeScreen`/`StationInfoScreen`/`HangarScreen`/`RepairFuelScreen`/`OutfitterScreen`/`ShipyardScreen`/`PlaceholderAreaScreen`; the area list is built from the data in `DockAreas`, the service registry instance lives on `GameSession.Services`, screens are registered in `ScreenRegistry`). The trade area draws its rows purely from `IStationService.Offers` and executes only via `IStationService.Execute` (`buy:<id>`/`sell:<id>`/`sell_all`; the UI never calls `TradeActions` directly), with list/tile toggle, tappable rows (quantity stepper, sum, buy/sell), the result message from `ServiceResult.Message`, a ship column (cargo, hold, credits real) and the best known selling station per good via `SpaceSim.Core/Trading/MarketInfo.cs` (`BestBuyerForGood`, `Classify` for scarcity/glut, with tests). Areas whose service the station does not offer are dimmed and open a short placeholder page (texts centralized in `UiPlaceholders.cs`); taxi and missions do not exist yet ("Bald"); "Reparatur & Tanken" is real since Phase 4c, "Ausrüster"/"Werft" since Phase 5c (see the Phase 5c section). Undo and price trends in trade, reputation/customs/lock level in station info, and foreign ships in the hangar are placeholders. Dock/undock logic (fly-in, hull repair, grace, autosave) stays in `Main.cs`, only the UI changed; "Abdocken" works from every area.

## Phase 4b (English summary): fuel economy — real consumption, refinery supply, no flat credit charge

**Content.** New station type `fuel_refinery` ("Treibstoffraffinerie", recipe 3 hydrogen + 1 energy → 4 `propellant` per 5 ticks; buildCost 9000 / upkeep 0.12 / income 1.5 like the other large refineries) and two start-world instances (id 25 in Beta at (-100,-60), id 26 in Alpha at (40,-115), `essential`, stock hydrogen 60/60, energy 120/100, propellant 100/100, default credits 10000), placed more than 101 units from every belt center and >50 from gates/stations so asteroid belts still reach their target count. `chem_engine_s` gains the module stat `fuelUse: 0.002`; `ShipStats` derives `FuelUsePerUnit` (sum of `fuelUse` stats). The dock shows propellant automatically through the existing `trade` service (market entries come from the recipe outputs) — no new service in 4b.

**Consumption.** `Travel.Start` no longer charges credits; it deducts `Refuel.Consume(ship, distance)` from the tank, where `distance` is the sum of the leg lengths (legs lie within sectors, so gate jumps stay free) and the units are `distance × Stats.FuelUsePerUnit / efficiency` of the active fuel. `EconomyRules.FuelCostPerUnit` stays as data only. New `Travel` helpers: `EstimateDistance` (straight-line in-sector distance), `PlannedDistance` (planned legs incl. detours), `EstimateFuel`. Player flight does not go through `Travel.Start`, so the player tank is untouched in 4b (tanking service comes in 4c).

**NPC refueling** (`Simulation/Refuel.cs`, pure functions over the universe, deterministic ordering): `ActiveFuel` (on-board fuel with highest efficiency, else first allowed), `Consumption`, `Consume`, `CurrentStation` (dock-point match), `FuelStations`/`NearestFuelStation`, `BuyFuel`/`TankUp` (market price, books stock, station credits, ship credits into the tank — not the hold — and publishes `FuelBought`), `EmergencyBuy` (2× base price, money sink paid to no station, rounds the amount up so the next fuel station is truly reachable, publishes `EmergencyRefuel`), `FuelPrice`/`TripFuelCost`, and `PrepareTrip` → `Depart` / `FuelStop` / `Stuck`. `PrepareTrip` treats the tank as sufficient only if it covers the trip **plus a reserve** (`MinFuelReserveFraction` = 0.75 × capacity) — otherwise refueling demand would hit all at once when the starting tanks run dry and no ship could reach a refinery anymore. It tanks at the current station if it sells fuel; else flies to the nearest reachable fuel station as a `GoToOrder` (tank on arrival in `TraderSystem`/`MinerSystem.Arrive`, then the real order is re-picked; a pending sell/deliver leg is re-attached to the best buyer); else buys emergency fuel and then flies to the fuel station; `Stuck` (broke / no fuel station) leaves the ship idling so `FleetSystem` abandons it as before. Both AI systems call `PrepareTrip` before every `Travel.Start` (buy leg, sell leg, field, delivery, leftover delivery). No ship may keep a ghost reservation: `GoToOrder` never reserves stock and is always paired with a transit.

**Route scoring.** `TraderSystem` subtracts `Refuel.TripFuelCost` (consumption of ship→buy→sell × fuel price at the current/buy station, else the average over fuel stations, else base price) from `margin × units`.

**Events / persistence.** New `FuelBought` and `EmergencyRefuel` events (bus only, not persisted). No new save fields — the save stays v5 (`Ship.Fuel` was already hashed and persisted in 4a), so save→load→continue remains bit-identical.

**Balance tool.** New `tank`/`notk` columns (cumulative `FuelBought`/`EmergencyRefuel` counts, also in the CSV) and a summary line: tank buys + cost, emergency buys + cost, propellant's average price ratio over the last 25%.

**Calibration.** `fuelUse` 0.002 with tank 200: 0.005 made propellant scarce (2.5–4× base) and squeezed the fleet, 0.003 hit the 3.0 warning and miners collapsed; 0.002 keeps the 20000-tick run green. 20000-tick balance run (default seed): exit 0, "Preise im Zielbereich", 14 traders / 8 miners (unchanged), 20 station tank-ups (24857 Cr), 0 emergency buys, propellant ≈ 0.61× base in the tail, energy and hydrogen columns in range (0.5–1.7, no degeneration vs the powerplant). Money: the old flat fuel sink is gone; fuel payments now flow ship→refinery, so ship credits end lower (~22k vs ~62k before) and station credits higher (~99k vs ~49k) — no knob was changed, the shift is the intended flow to the refinery.

**Tests.** New `tests/SpaceSim.Tests/FuelEconomyTests.cs` (8 tests): consumption counts only in-sector legs (gate jumps free) and leaves credits untouched, model-less ships consume nothing; tank-up at the current station with exact stock/credits/cost bookkeeping; station without fuel → fuel stop as `GoToOrder` + tank on arrival; emergency buy (2× base, sink, amount = ceil to reach the next station, then fuel stop) and broke → `Stuck`; refinery produces propellant (H2/energy down, stock up) and sells to a ship with correct credits/stock; trader scoring subtracts fuel cost (huge `fuelUse` → no order; control case picks one); determinism (same seed → same hash, save→load→continue bit-identical); 20000-tick invariants (no negative or over-cap tank, no ship in transit past its arrival, no ghost `GoToOrder`, tracker consistent, player tank still 200). `FuelModelTests`/`ContentTests` were adjusted where 4b changed their assumptions (refineries now trade propellant, `Travel.Start` is no longer credit-flat, tanks are not full after a run). 273 tests green, `dotnet build` 0 warnings, Godot selftest OK.

**Fuel supply fix.** `fuel_refinery` has a second recipe without inputs (base production, 1 propellant per 20 ticks) so fuel never runs out when the hydrogen chain stalls; over 60000 ticks propellant stays out of the warning band on all tested seeds (before: 4× base on 5 of 8). **Known weaknesses.** On some seeds food/life support tip into the warning band at 60000 ticks (traders fall into back-and-forth hauls of single goods; independent of fuel). Blocking non-producer→non-consumer trade saturates the whole economy (all prices ~0.3×) and was rejected.

## Phase 5b (English summary): player wallet — money belongs to the person, not the ship

## Phase 5c (English summary): outfitter, ship purchase, trade station, skiffs, start packages

**Shared fit rule.** `Model/FitRules.Check(slotTypes, modules, class, slots, fit)` is the single pure rule for a valid fit (fit length = slot count, known module, slot type, module size ≤ slot size, required slots filled, power balance Σ output ≥ Σ draw and peak − surplus ≤ storage), returning a `FitIssue(Kind, Slot, Message)` or null. `WorldBuilder.LoadSlotContent` uses it for ship models (same messages, prefixed with the model name) and the outfitter uses it at runtime, so content validation and refitting can never diverge. `FitRules.SlotIssue`/`PowerIssue`/`Describe` are the parts.

**Outfitter service (`Services/OutfitterService`, key `outfitter`).** Available at stations whose market holds module goods. Offers per slot: `remove:<slot>` for filled non-required slots (Price = the station's buy-back price, 0 = module goes to the hold) and `fit:<slot>:<module>` for every module of matching slot type and size that is in the ship's hold (free) or in the station stock (market price). Amount = 1 only if the change is valid and affordable; `OutfitterService.Preview(u, station, ship, slot, module)` (pure) returns before/after `ShipStats`, the `FitIssue` and a cargo problem — used by `Execute` and by the UI. Rules: required slots (reactor, engine) only by swap; the swapped-out/removed module is sold to the station at market price when it accepts (`AcceptableUnits ≥ 1`, credits), else put in the hold; the existing cargo must still fit the new hold (`CargoProblem`, same form rule as `Ship.FreeVolumeForForm`); money via `Universe.WalletOf`. After the change `Ship.RecomputeStats`, `CargoCapacity = Stats.Cargo`, hull clamped to `MaxHull`. Any failure (strict key parsing, slot type, size, power, peak, required slot, cargo, stock, credits) changes nothing and publishes nothing; success publishes `ServicePerformed` and `ShipRefitted`. Ships without a model cannot be refitted. `OreChunks.TryFire` returns `MineResult.NoLaser` and the mining autopilot stops when the fit has no `Mining` module.

**Ship purchase.** `Simulation/ShipPurchase` is the shared buying rule: `Materials(u, class, fit)` = 1 kit of the class (`KitKeyOf`) + one module good per fitted module (aggregated, GoodId order; null if a good is missing), `Missing(station, needs)`, `Price` = Σ units × station market price (base price if not traded) × (1 + assembly), `Consume`, `Sells(u, station, class)`, `Create(...)` (new ship at the dock point with copied slots/fit, full hull and tank). Station types carry an optional `ShipDealerConfig` (JSON `shipDealer: { classes, maxSize, assembly }`, validated against the ship classes, saved in `StationTypeSave.ShipDealer`): the shipyard sells all classes (assembly 0.05), the new trade station only `skiff` up to size S (assembly 0.10). The refinery gets no ship dealer (its planned classes "light miner"/"small tanker" do not exist yet). **Service `shipdealer` (`Services/ShipDealerService`):** offers `buy:<model>` per model the station may sell (ordinal key order), Amount = 1 if all materials are in stock and the wallet can pay; `Quote(u, station, buyer, model)` gives stats, price, materials and what is missing. `Execute` (player only) consumes kit + modules from the station stock, pays the station from the player wallet, creates a player-owned ship (`Controller.Player`, role Player, wallet faction) at the dock point, publishes `ServicePerformed`, `ShipPurchased`, and makes it the active ship.

**Several player ships.** No new save field was needed: every ship with `Controller.Player` belongs to the player and books on the wallet; `Universe.PlayerShip` is the active one (now part of `UniverseHash`). `Simulation/PlayerFleet`: `Owned`, `ParkedAt(u, station)` (own, not active, no transit, same sector, within 30 of the station centre) and `SwitchTo(u, station, id, out message)` — the previous active ship is parked at its dock point, `PlayerShip`/`PlayerSector` switch, `ActiveShipChanged` is published. Parked own ships are ignored by all AI systems (role Player) and shown by `Materializer` like other ships. The view: after a purchase the shipyard screen updates `DockContext.Ship`; `Main.OnActiveShipChanged` (event) resets dock context, ore chunks and auto-mining; the hangar lists own ships parked here with "Übernehmen" (`Main.SwitchShip` → `PlayerFleet.SwitchTo`); the dock menu shows them as chips. Switching from afar (command centre) stays a Phase 12 topic.

**AI fleet (`FleetSystem.Expand`).** The AI prefers the same rule: if a reachable station that sells the parent's class has the kit and all modules of the parent's fit, it consumes them and the yard receives `ShipPurchase.Price`; otherwise it falls back to the pre-5c rule (kit only, `NewShipCost`), so module shortages never block fleet growth. `EconomyRules.FleetBuysModules` (default true; false = always kit only). New event `FleetShipBuilt(ship, yard, withModules, price)`; the balance tool prints "KI-Neubauten: n mit Modulen, m nur aus dem Bausatz". Without the fallback, seed 2 stalled at 12 traders because the drive works could not deliver engines (see weaknesses).

**Production order.** `ProductionSystem` now runs the recipes of a station that are due in the same tick in order of output scarcity (Σ market price / Σ base price, ties by list order). Only stations with several recipes are affected (module factories, shipyard kit tiers, refinery); before, the module key order let cargo modules on overstock eat the steel/electronics the scarce reactor needed. Changes NPC behaviour (different hashes).

**Content.** New station type `trade_station` "Handelsstation" (no recipes, `stocks` only: `ship_kit_light` and the skiff/outfitter modules at [1,3]; services `trade`, `outfitter`, `shipdealer`; buildCost 8000, upkeep 0.08, income 0.8) and one instance "Handelsstation Beta" (id 30, Beta (-120,60), the hub sector, essential); `maxStations` 33→34 so the lifecycle keeps its headroom. **Quality grades (`Simulation/ShipQualityRoll`).** `Model/ShipQuality.cs`: `ShipQuality { Standard, Improved, Elite, Masterwork }` (German names via `ShipQualityNames`) and `UpgradeKind`. `RollGrade` draws exactly one `Universe.Rng` value; `Roll(u, cls, slots, fit, yard, baseNeeds)` applies the grade and falls back one grade at a time when it is not possible: Improved = one module upgraded (random among slots with an upgrade path), Elite = 2–3 modules upgraded, otherwise one non-required slot one size larger (slot material from stock), Masterwork = Elite plus a bonus slot (copy of the first cargo slot with the same module), bonus slots and enlarged slots limited by `MaxSlotUpgrades`; the final fit must pass `FitRules`. The extra cost comes from the yard stock: better modules, the bonus module and slot material must be in stock in addition to what the purchase consumes anyway, while the replaced base modules are no longer consumed (`QualityOutcome.Materials` = the full need); the buyer pays the normal price. Used by the player purchase (`ShipDealerService`, message names the grade), the AI fleet (both the model-choice and the clone path; the clone now copies the parent's *model* — class slots and factory fit — not its individual quality/upgrades) and the founder ships of the start world (`WorldBuilder`, AI ship groups only, without material; `rules.founderQuality` false disables it — tests that rely on the plain unit fleet use `QualityUpgradeTests.WithoutFounderQuality()`). The player's start ship does not roll. Event `ShipQualityRolled(ship, rolled, grade)`. `Ship.Quality` is saved and displayed; its effect lives in `Slots`/`Fit`.

**Upgrades (`Simulation/ShipUpgrade`, shared rule).** `Quotes(u, station, ship)` lists every upgrade with chance, pity, materials, missing stock, price, affordability and an issue text: `module:<slot>` (module → `UpgradeTo`, chance by the module's tier, the resulting fit must pass `FitRules`), `slot:<slot>` (non-required slot one size larger) and `bonus:<slotType>` (new empty slot of a non-required type present on the ship; slot upgrades share `SlotUpgradeChance` and the class limit — "Slot-Upgrades ausgeschöpft"). Price = material at the station's price × (1 + `UpgradeLabor`), paid via `Universe.WalletOf(ship)` to the station; material comes from the station market and is consumed on success and failure. Chance = base + `UpgradePityStep` × `Ship.UpgradePity[slot]` (key −1 for bonus slots), capped at 1 — every failure raises the next chance, success resets the counter, so with the defaults a module upgrade is certain after 1 failure and a slot upgrade after at most 9. `Attempt` rolls `Universe.Rng`, applies (fit, slot size, or a new empty slot + `null` fit entry), recomputes stats/cargo/hull and publishes `UpgradeAttempted(ship, station, kind, slot, from, to, success, chance, price)`.

**Service `upgrade` (`Services/UpgradeService`, registered after `shipdealer`).** Offers = one per quote (`Amount` 1 only when possible; `Held` = pity), strict keys, `Describe` for the text. `Execute` refuses (no state change, no event) unknown keys, issues, missing material and missing credits; otherwise it attempts and returns `Success` = executed, `Units` 1/0 = upgrade succeeded/failed, and publishes `ServicePerformed` in both cases (material and credits are gone either way).

**NPCs (`Simulation/UpgradeSystem`, new `UpgradeModule` after Trade, every tick).** Economy-AI ships with a model, idle (no transit/order), with ≥ `UpgradeMinCredits` and sitting at the dock point of a station whose type lists `upgrade` pick the module upgrade with the best expected gain per credit (Δ `FleetValue` of their current job × chance ÷ price, price ≤ `UpgradeBudgetShare` × credits) and attempt it with the same rule. NPCs never do slot upgrades (they do not refit).

## Phase 8 (English summary): construction sites, construction ships, emergency build, Essential split, asteroid breaker, warehouse

**Build sites.** A build site is a `Station` of the content type `build_site` ("Baustelle", no recipe, service `trade`) with a `Station.Site` record (`Model/BuildSite.cs`: target `TypeKey`, `Required` bill, investor station/ship, `Budget`, `Builder`, `StartedTick`, `LastProgressTick`, `BlockedSince`, `AssemblyTicks`, `Emergency`, `Abandoned`). Being a station it is an obstacle, rendered, dockable and part of `StationsTrading`, so traders, the player's trade area and the dock UI work unchanged. Its market holds one entry per material: `Amount` = delivered, `Target` = required; `Station.AcceptableUnits` returns exactly the missing amount (0 when abandoned); `MarketSystem` bids a fixed `BasePrice × ConstructionPriceFactor` (1.25); `UpkeepSystem` skips sites (no upkeep, no wealth tax on the escrow); `TradeActions.Buy/MaxBuyable` refuse a live site (abandoned sites sell their stock); `EconomyStats` excludes sites from price averages and counts them separately (`EconomySnapshot.Sites`, `Builders`; `Stations` = finished stations). `StationLifecycleSystem` only decides *whether* to build: it excludes sites from the scarcity/glut measure, allows at most `MaxActiveSites` (2) live sites and never two of the same type, takes investors only from finished stations/AI ships, and — when `ConstructionRules.UsesSites` (rule `ConstructionSites` true, the site type exists and the bill resolves) — calls `ConstructionRules.StartSite` (investor pays `BuildCost × StationBuildCostFactor` into the site as escrow, `ConstructionStarted`; an abandoned site in the chosen sector is reused with its material). Otherwise the old direct build applies (very old saves without good keys). Sites count against `MaxStations`/`MaxStationsPerSector`.

**Bill (cycle-free).** `ConstructionRules.Bill(u, type)`: the type's own list (`stationTypes[].construction`, validated: known goods, > 0, never a good the type produces) or the rule: `BuildCost × ConstructionMaterialShare` (0.5) split by `ConstructionMaterials` weights (steel 0.4, hull plates 0.35, electronics 0.25) into units at base price (≥ 1); goods the type produces are dropped and their weight goes to the rest (steelworks need no steel, plating works no hull plates, electronics fabs no electronics). null = a material good is missing in this world (fallback to direct build). Content test: no type requires a good only it produces; every material has another producer type present in the start world.

**ConstructionSystem** (new `ConstructionModule` "Construction" after Trade/Upgrades, before Lifecycle; runs every tick). Sites: assembly runs (`AssemblyTicks += dt`) while everything is delivered and the assigned builder is parked on site (or after an emergency build); after `ConstructionAssemblyTicks` (200) `ConstructionRules.Complete` replaces the site in place by a station of the target type (same id/position/owner, `StationFactory` market and recipes, 2000 start credits as before), pays the builder `ConstructionFeeShare` (10 %) of the budget from the escrow, the rest of the escrow is the credit share (vanishes like the old build cost), publishes `StationBuilt` + `ConstructionCompleted`. Expiry: no progress for `ConstructionExpiryTicks` (8000) and not blocked → escrow back to the investor, material stays (`Abandoned`, "Verlassene Baustelle", reused by the next project in the sector, sellable to the player) or the site disappears without material (`ConstructionAbandoned`); abandoned sites without stock are removed. Builders (role `ShipRole.Builder`, capability `Construction`, `Ship.IsAiBuilder`) are the executors of the new job `BuildJob` ("build", limit `MaxBuilders` 4, 1 unit per ship, registered in `ShipJobs.Default` after trade/mine so `FleetSystem` can also buy them): they take an unassigned site (own faction first, then travel time), fetch missing material at the nearest supplier (`ConstructionRules.Suppliers`: finished stations that produce the good or hold it as stock-only — warehouse, trade station — never consumers' inputs, price ≤ `BasePrice × ConstructionMaxBuyFactor` 2.0), paid from the escrow, deliver (`ConstructionDelivered` "builder"), and wait on site for assembly; refuel via `Refuel.PrepareTrip` like traders; order `BuildOrder(Site, Supplier, Good)` (saved as kind "build"); leftover cargo is sold at the best buyer. Traders deliver through normal trade: `TraderSystem.BestTrade` subtracts what other traders already bring to a site (incoming reservation, sites only), the trade is booked as usual and `ConstructionRules.OnDelivered` marks progress (`ConstructionDelivered` "trader"/"player"); a trader whose seller no longer trades the good (site completed) is re-routed to the best buyer instead of dumping. A builder that loses its rig is released and the site becomes free.

**Emergency build (Notbau).** A site is blocked (`ConstructionRules.IsBlocked`) when no builder is assigned and none is reachable, or a missing good has no reachable supplier at the price cap, or the escrow cannot pay one unit at the cheapest supplier. After `EmergencyBuildTicks` (2000) blocked — × `EmergencyCriticalFactor` (0.5) for critical sites — and if the owner faction's `LastEmergencyBuildTick` is older than `EmergencyBuildCooldown` (3000, the brake: one emergency build per faction per cooldown), `ConstructionRules.Emergency` creates only the missing materials for `BasePrice × EmergencyBuildMarkup` (2) from the escrow (money sink; an uncovered rest is waived and reported), sets `Emergency` (assembly without builder) and the faction timestamp, publishes `EmergencyConstruction`. Blocked sites do not expire.

**Essential split (small).** `Station.Essential` is now `Station.BankruptcyProtected` (JSON `essential` stays an alias, `bankruptcyProtected` accepted; save field `BankruptcyProtected`, old `Essential` still read). `Critical` is derived, never saved (`Simulation/StationCriticality`): `IsCritical(u, station)` = the only reachable finished producer of one of its goods (such stations are not removed for bankruptcy), `IsCriticalSite(u, site)` = the target type produces a good no reachable finished station makes, or a good of `rules.criticalGoods` (steel, hull plates, light ship kit). The rest of the split (`Government`, `Capturable`, `Destructible`, `Immortal`) stays Phase 10.
