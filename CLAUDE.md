# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Mobile-first 2.5D space game (inspired by Interstellar Pilot 2) with a fully autonomous economy and factions that run without player input. The world is a graph of sectors; each sector is its own instance and the only way between them is via jumpgates. Stack: engine-independent C# core + Godot 4.7.2 (.NET build) as the view. The user communicates in German.

**Architecture is the top priority.** Features must be added as separate modules/systems behind clear seams (registration, interfaces, events, data files), not by growing central classes. Keep `SpaceSim.Core` free of Godot and file IO.

## Commands

The .NET 10 SDK is installed; `SpaceSim.Core` targets `net8.0`, the test and tool projects `net10.0`, the Godot project `net9.0` (the Godot 4.7 Android template only accepts net9.0 for C#).

```
dotnet build                       # solution (Core, tests, balance tool; NOT the Godot project)
dotnet test                        # all unit tests (~5 s, includes long deterministic runs)
dotnet test --filter "FullyQualifiedName~Economy_RunsStably_WithoutPlayer"   # single test
dotnet run --project tools/SpaceSim.Balance -- --ticks 60000 --every 5000    # headless economy report (also: --seed N --world file.json --csv out.csv); exit code 1 if prices degenerate

dotnet build godot                 # build the Godot C# project
godot-mono --path godot            # run the game (use godot-mono, NOT godot: plain godot cannot run C#)
godot-mono --path godot -e         # open the editor
godot-mono --headless --path godot --fixed-fps 60 -- --selftest   # scripted headless run: autopilot across sectors, docking, panels, save/load; prints SELFTEST OK, uses its own save file
```

`godot-mono` is a symlink in `~/.local/bin` to `~/.local/opt/godot-mono/`. Godot prints harmless "Leaked unsafe reference"/ObjectDB warnings when quitting from code.

## Core architecture (`src/SpaceSim.Core`)

**Two layers.** Simulation layer: every sector exists as plain data in `Universe` and is always simulated. Presentation layer: only `Universe.PlayerSector` is materialized as a Godot scene. Core must never reference Godot; the view must not invent simulation state.

**Modules and systems.** `SimulationRunner` builds its system list from `ISimModule`s (`Modules/DefaultModules.cs`: Production, Resources, Trade, Lifecycle) via `SimulationBuilder.Add(system, interval)`. Order matters (production/market before AI, lifecycle last). A system with `interval > 1` runs every n ticks and receives `dt = n` (simulation LOD) — it must scale by `dt`. To add behavior: write an `ISimSystem`, register it in a module (or a new module in `DefaultModules()`).

**Events.** `Universe.Events` (`SimEvents`) is a synchronous bus (`TradeCompleted`, `MineDelivered`, `StationBuilt/Removed`, `ShipSpawned/Removed`). Stats, UI toasts etc. subscribe; systems publish. The bus is not persisted — re-subscribe after loading (the view does this in `Main.AttachSession`).

**Content is data-driven.** `Content/default-world.json` (embedded resource) defines goods (22: six raw ores, refined goods, components, end goods, `ship_kit`; referenced by string key `Good.Key`, `GoodId` = index+1, with a UI `color`), asteroid classes (ore mixes), station types with recipes (18), factions, sectors, gates, stations, belts (fields), ships. Ore chain: 6 ores (iron, ice, copper, silicon, titanium, platinum) → refined (steel, water, hydrogen, copper, wafers, titanium, platinum, energy) → components (electronics, hull plates, fuel cells, life support) → end goods (food, consumer goods, luxury goods, ship kit). `DemoUniverse` has `GoodId` constants for the default world; `ContentTests` guards them and the chain's consistency. `WorldBuilder.Parse/Build` validates and throws `WorldFormatException` with the offending name — including the slot sections: duplicate keys, unknown slot type/size/class/module keys, unknown goods in a module's `cost`, unknown `grants` names, module larger than its slot, module slot type mismatch, fit length ≠ slot count, empty required slot, and the power balance (Σ powerOutput ≥ Σ powerDraw; Σ peakDraw − (powerOutput − powerDraw) ≤ Σ powerStorage). `DemoUniverse.Create()` is just `WorldBuilder.BuildDefault()`. Core never reads files; callers pass JSON text. The file also has optional `slotTypes`/`modules`/`shipClasses`/`shipModels` sections (missing sections = empty registries on `Universe.SlotTypes/Modules/ShipClasses/ShipModels`) and `goods[].form` (`solid` default, `liquid`; content only, not persisted, old saves stay v3-loadable). `goods` carry `Good.Form`; `Model/ShipStats.Compute(class, fit)` derives power/cargo/hull/mass/thrust/speed (clamped to `ShipStats.MaxSpeed`)/upkeep/capabilities/laser tier as a pure function. Phase 3a added all of this as data only; Phase 3b wires it up: every ship carries `ModelKey` ("" = no model, legacy ships keep the old flat values), its `Slots` list (default: the model's class slots) and its `Fit` (module key per slot, null = empty), plus the derived `Ship.Stats` — `Ship.RecomputeStats(u)` recomputes after Fit/Slots changes and on load (without a resolvable model the fallback is hull 100). `Ship.MaxHull` is now an instance property from `Stats.Hull` (the const is gone; the view uses `ship.MaxHull`); `CargoCapacity` stays a field for its many consumers but is set from `Stats.Cargo` at creation/load when a model exists; capabilities come from `Stats.Capabilities` unless explicitly set (`CapabilitiesSet` semantics unchanged, a saved value wins over the model). `Travel.Plan/Start/Estimate/Ticks` take an optional ship and use `Travel.SpeedOf(ship)` = `Stats.Speed` when a model is present, else the `ShipSpeed` constant — all unit models are 8, so travel is unchanged. World JSON: `ships[]` groups and `player` accept an optional `model`; if absent, `WorldBuilder.NewShip` picks the unit model by role+cargo (`UnitModelFor`: trader/100→`unit_trader_100`, trader/60→`unit_trader_60`, miner/100→`unit_miner_100`, miner/60→`unit_miner_60`, player→`unit_player`, else "" e.g. Fighter); an unknown explicit key throws `WorldFormatException`. `FleetSystem.Expand` copies model/slots/fit from the parent ship. Save v4: `ShipSave` gains `ModelKey`, `Slots`, `Fit`, and the four slot-content sections (`SlotTypes`/`Modules`/`ShipClasses`/`ShipModels`) are persisted in the save like the other content (goods, asteroid classes, station types incl. recipes), so a save is self-contained; `MigrateV3ToV4` sets only `ModelKey` per role/cargo and injects the embedded default-world slot registry (v3 saves contain no slot content), and on load `Slots`/`Fit` are filled from the model when the save lacks them; `UniverseHash` additionally hashes `ModelKey` and `Fit`. The unit models reproduce the old flat values exactly (cargo 100/60, hull 100, speed 8, role-derived capabilities), so behavior, `UniverseHash` roundtrips and the balance run are unchanged apart from the hash value. Tuning knobs live in `EconomyRules` (JSON `rules` section, also saved).

**Space and travel.** Entities reference each other by typed ID structs in dictionaries on `Universe`. Jumpgates are the edges of the sector graph (`Universe.FindRoute`, per-tick cached via `CachedRoute`/`IsReachable`; `Gate.Open=false` blocks). Ships outside the player's sector have no physics: `Travel.Plan` turns a trip into contiguous `Leg`s (one per sector, detouring around obstacles via `PathPlanner`), `Transit` stores them, `ArrivalTick` is the last leg's end. `Travel.Start` also charges fuel (a money sink). `Travel.Estimate` is the cheap (straight-line) variant for AI scoring. Obstacles (`Obstacle`, built by `Universe.GetObstacles`) are asteroids (`Asteroid.ToObstacle()`, generated by `Demo/AsteroidGenerator`) and station bodies. Ships target `Station.DockPoint(shipId)` / `ResourceField.WorkPoint(shipId)`, never centers. `Ship.Position`/`Sector` are only updated on arrival; mid-trip location comes from the legs.

**Ship index.** `Universe.Tracker` (`ShipTracker`) maps sector → parked ships / ships with a leg in that sector. Always mutate ship placement through `Universe.AddShip/RemoveShip/StartTransit/FinishTransit/MoveShip`, never by writing `Ship.Sector`/`Transit` directly. `Materializer.Snapshot(u, sector, fractionalTick)` uses the index to derive where each NPC ship is (moving ships by interpolating the active leg, parked ones at `Ship.Position`); the view renders that.

**Capabilities and controller (Phase 2).** `ShipRole` is still the stored current-task label (save format, display), but systems decide by capability, not by role: `Ship.Capabilities` (`[Flags] Capability`: `Cargo`, `Mining`, `Combat`, `Construction`, `Salvage`, plus `Jump`/`Stealth` which exist but are unused until the deferred jump-drive/cloak modules, no `Research`) and `Ship.Controller` (`Ai`/`Player`, checked via `Ship.IsPlayer`). Both are saved (`ShipSave.Capabilities` int / `Controller` string, nullable, so the format stays v3; old saves without them derive from the role) and part of `UniverseHash`. `CapabilityDefaults.ForRole/ControllerFor` derive them from the role at the creation points (`WorldBuilder.NewShip`, `UniverseSerializer.FromSave` for old saves, `FleetSystem.Expand`) and in `Universe.AddShip` only when the creator never set them (`Ship.CapabilitiesSet/ControllerSet` flags, set by the property setters), so an explicit `Capability.None` is a valid value. Ships with a resolvable model (Phase 3) always take `Capabilities` from their fit (`Ship.RecomputeStats`), so removing a module takes effect even after load; the saved value only counts for model-less ships. `TraderSystem`/`MinerSystem` keep the role as the task filter and additionally require `Has(Capability.Cargo)`/`Has(Capability.Mining)`; a ship that lacks it is released via `JobRelease.Release` (order and reservation dropped, a running transit is flown to its end and finished without trading/mining, cargo stays) instead of being skipped — skipping froze such ships mid-transit with a ghost reservation; `FleetSystem`, `UpkeepSystem`, `EconomyStats` and `StationLifecycleSystem` count economically active AI ships via `Ship.IsEconomyAi` (Controller Ai with Cargo or Mining); `TradeActions` (PlayerSold/PlayerBought) and `Materializer` recognize the player via `IsPlayer`. Pure display (ship colors in SectorView/SectorScreen, `ShipSnapshot.Role`) may still use the role.

**Economy.** Price per station and good = `BasePrice * clamp(Target / max(Amount,1), 0.25, 4)` (`MarketSystem`). `ProductionSystem` runs station recipes. `TraderSystem` scores routes by profit per tick (margin × units / `Travel.Estimate`) with stock reservations by other traders; stations only pay what they have (`TraderSystem.CanAfford`, leftover cargo is dumped). `MinerSystem` mines belts and refuses to mine when the mix is worth less than `MinPriceFactor` × its base value. Prices: besides the stock price, a factory bids at most `InputWillingness` of its products' value for inputs (`MarketSystem`, stops price spikes from bankrupting processors); stations accept only up to `Target × OverstockFactor` (`Station.AcceptableUnits`) and production pauses when outputs exceed that (`ProductionSystem`). Money flow (`UpkeepSystem`): station income (faucet) and upkeep, wealth taxes, ship upkeep, fuel, ship/station purchases (sinks); without sinks credits pile up at ships. `StationLifecycleSystem`: bankrupt non-`Essential` stations are removed (`Universe.RemoveStation` cancels referencing orders), scarce goods (avg price > `BuildPriceRatio`) trigger a new producer station funded by the richest station *or ship* (investors). `FleetSystem`: rich ships buy ships up to `MaxTraders/MaxMiners` — but a new ship needs a **ship kit** (`EconomyRules.ShipKitGoodKey`, made by shipyards from hull plates, electronics and fuel cells, i.e. from titanium/platinum chains) from a reachable yard, which receives `NewShipCost`; the ship appears at the yard. Idle broke ships are abandoned; idle ships back off their re-planning (`TraderSystem.IdleBackoff`). Scarcity/glut for station construction is measured on stock ratios, not prices. Idle AI ships only re-think every ~10 ticks (`Ship.NextThinkTick`).

**Determinism.** All randomness goes through `Universe.Rng` (`DeterministicRng`, state saved). `Diagnostics/UniverseHash` hashes simulation state; tests assert same seed → same hash and save → load → continue is bit-identical. Never use `System.Random`/time/hash-order-dependent iteration inside systems.

**Persistence.** `Persistence/SaveGame` DTOs (versioned, currently v4; `MigrateV1ToV2` converts the old field-owned ore into asteroid ore, `MigrateV2ToV3` the single-ore fields/asteroids into `legacy_<good>` classes (mine orders now reference a field index), `MigrateV3ToV4` assigns ships their `ModelKey` (unit model by role/cargo) and injects the default-world slot content, `Migrate` hook in `SaveGameJson`) are separate from the runtime model; `UniverseSerializer` converts both ways (slot content sections included, `Ship.RecomputeStats` after loading); derived state (Events, Tracker, caches) is rebuilt. When adding persistent state to `Universe`/`Ship`/`Station`, update DTOs + serializer + `UniverseHash` and bump `SaveGame.CurrentVersion` with a migration if the format breaks. `OfflineCatchUp` replays missed time (capped at 10k ticks, `SimClock` = 4 ticks/s; ~0.3 ms/tick on desktop).

**Navigation/avoidance/collision.** `Navigator.Next` gives the player autopilot the next waypoint (route gates + `PathPlanner`). `Collision.Resolve` (circles) is applied to the player in the view (`PlayerShip`): hard impacts on asteroids/stations (> `HardImpact`) damage the hull unless the ship is in `Grace` (after undock/respawn/jump); NPC ships only push softly and never damage; a lateral-damping flight assist and braking keep the ship from drifting into obstacles, and the autopilots slow down near obstacles (`Main.ClearanceScale`). Docking makes the ship fly into the station, become invisible and collision-free, and repairs the hull; undocking reverses it; `Avoidance.Desired` is a purely cosmetic sidestep between NPCs/player in the view. Neither feeds back into the simulation, so two NPC fleets may still cross in the data model. `PathPlanner` recursion is bounded by `MaxDepth` and a `MaxExpansions` node budget. Keep asteroid sizes in the view equal to `Obstacle.Radius`.

**Asteroids, ore and respawn.** `Asteroid` (Model/Asteroid.cs) carries its own finite ore (`Ore`/`MaxOre`) and a `ClassKey`; `AsteroidClass` (content) defines a weighted ore mix (`Yields`), `ChunkChance` per shot and `OreFactor` (richness). Ore type is rolled **per chunk**, not per asteroid. Asteroids shrink while mined (`Radius` depends on remaining ore) and are removed at 0 (`AsteroidDepleted`). Ore-bearing asteroids belong to the belt of the nearest `ResourceField` with the same class (`Sector.FieldFor`, `MiningRules.BeltRadius`); background rocks have no class/ore and are just obstacles. A field is only a belt descriptor (`ClassKey`, `Position`, `TargetAsteroids`, `RespawnTicks`); its ore is the sum of its asteroids (`Belt.OreIn`). `AsteroidRespawnSystem` (ResourceModule, interval 10) regrows missing belt asteroids with random ore, deterministically via `Universe.Rng`, never within 45 units of the player ship. Placement rules are shared by world generation and respawn (`BeltPlacement`).

**Player mining.** `Mining/OreChunks` is a real-time, non-persisted micro-simulation for the player's sector: the laser is fired **one shot at a time** (`TryFire`; a trigger that arrives during the reload time `ShotInterval` returns `Cooldown`, holding does nothing — the automatic mode simply re-triggers every frame). Every shot goes through the shared rule `Mining/LaserShot.Roll`: with the asteroid class's `ChunkChance` it releases a chunk of a random ore type (class weights) whose size is random (`MiningRules.ChunkTable`, small common, large rare), capped by the asteroid's ore. Each shot also gives the shooter a **recoil** impulse (`RecoilImpulse`, away from the asteroid): real velocity change for the player (`Main.OnShot`), a decaying visual kick for NPC markers (`SectorView.Kick`) because NPC positions are simulation data. The ore leaves the asteroid when the chunk is released; the tractor beam (`Update`) pulls chunks in and loads them (partially if the cargo is nearly full); uncollected chunks expire and their ore is lost. `Mining/MiningAutopilot` is the automatic mode (seek asteroid → approach → fire + tractor → when full go to the best buyer, dock, sell → repeat; other sector if this one is empty); it only returns a `MiningStep` (what the view should do), so it is tested with a kinematic harness in `MiningTests`. `Trading/TradeActions.SellAll/Quote/BestBuyer` implement selling with the same payout rules as NPC trade. NPC miners fire the same shots inside the simulation (`ShotTimer` reload, `u.Rng`, max one shot per tick, ore taken from the asteroid into cargo, `MinerShot` event per shot). A `MineOrder` names a belt (`Field` index) and a destination station; since chunks are mixed, the miner scores stations by the expected value of the mix (`MixValue`), sells what the station accepts via `TradeActions.SellAll` and drives leftovers to the next best buyer (or dumps them); fields with other miners are penalised (`CrowdPenalty`, herd protection). The view draws NPC lasers/flying chunks/recoil only from those `MinerShot` events when they happen in the player's sector, so what you see is exactly what the simulation did. Expected NPC yield: `MiningRules.ExpectedOrePerSecond`.

**Diagnostics.** `EconomyStats.Snapshot` and `RouteRecorder` (event-based) feed the in-game economy panel and `tools/SpaceSim.Balance`. Use the balance tool after any economy change: it caught money explosions and herding that unit tests missed.

## Godot project (`godot/`)

`godot/SpaceAdventure.csproj` (Godot.NET.Sdk/4.7.2) references the Core and is deliberately **not** in `SpaceSim.slnx`. `scripts/Main.cs` is only the composition root (wiring, steering priority throttle slider/turn buttons > pointer > autopilot, gate jumps, docking). ## Phase 3c (English summary): laser tier and cargo form in the hold

**Laser tier.** `LaserShot.Roll(rng, cls, rock, chunkChanceMult = 1f, chunkSizeMult = 1f)` scales the chunk chance (`ChunkChance * chunkChanceMult`, clamped to 1) and the chunk size (`* chunkSizeMult`, still capped by the asteroid's remaining ore). The RNG call order is unchanged at factor 1, so determinism holds. The player path (`OreChunks.TryFire`) and NPC miners (`MinerSystem.Mine`) pass `ship.Stats.LaserChunkChanceMult/SizeMult`; a ship without a model has 1/1.

**Cargo form.** `ShipStats` additionally derives `CargoSolid`, `CargoLiquid`, `CargoAny` (sum of `capacity` over the cargo modules by `holds`; `Cargo` stays the total). New rule on `Ship`: `HasSeparatedHolds` (model with at least one solid/liquid cargo module), `CapacityVolumeFor(form/good)` (solid+any resp. liquid+any; total capacity without separated holds) and `FreeVolumeFor(u, good)` / `FreeVolumeForForm(u, form)` — a ship without a model or with only `any` modules behaves exactly as before (one shared hold, `CargoCapacity - UsedVolume`); with separated holds the `any` space is shared, legal iff `usedSolid <= solid+any`, `usedLiquid <= liquid+any` and `usedSolid+usedLiquid <= solid+liquid+any` (all in volume = units × VolumePerUnit). All former `CargoCapacity - UsedVolume` sites now use the per-good rule: `Ship.FreeUnits` (hence `TradeActions.Buy/MaxBuyable`), `TraderSystem` route planning (capacity per good, skips goods that don't fit at all) and the buy amount on arrival, `MinerSystem` (ore is solid: mine-time estimate, affordability, cargo-full check, per-shot load), `OreChunks.TryFire` (cargo-full check, in-flight chunks counted per form) and `MiningAutopilot.NearlyFull`. `CargoCapacity` remains the total. `Good.Form` is now persisted in the save (`GoodSave.Form`, optional string, additive — no version bump, old saves load as solid).

**Content.** `default-world.json` gained only test-example modules that no start-world ship uses: `cargo_solid_s` (holds solid, capacity 30), `canister_bay_s` (holds liquid, 30), `cargo_universal_70` (holds any, 70). Test-only ship classes/models (e.g. the `tanker_test` canister ship) are injected by mutating the default world JSON in tests, not in the default world.

**Tests.** New `tests/SpaceSim.Tests/CargoFormTests.cs`: `Roll` at factor 1 is identical to before (same RNG sequence/results), chance factor 2 raises the hit rate (fixed seed, 2000 rolls), chunk sizes scale and stay capped by the asteroid; player and NPC wiring use the ship's laser tier; solid-only ship cannot buy water (`MaxBuyable` = 0, `Buy` → `NoSpace`), tanker buys water but no iron, universal hold shares between forms, no-model ship behaves as before, every good has a form and every unit model carries all goods of the start world, and a long run with a test tanker in the world keeps the volume invariant for every ship and the tanker never carries or orders solids. Unit models are unchanged in behavior: all previous tests pass unmodified and the 20000-tick balance run is byte-identical apart from the timing on the hash line (hash value unchanged).

## Phase 4b (English summary): fuel economy — real consumption, refinery supply, no flat credit charge

**Content.** New station type `fuel_refinery` ("Treibstoffraffinerie", recipe 3 hydrogen + 1 energy → 4 `propellant` per 5 ticks; buildCost 9000 / upkeep 0.12 / income 1.5 like the other large refineries) and two start-world instances (id 25 in Beta at (-100,-60), id 26 in Alpha at (40,-115), `essential`, stock hydrogen 60/60, energy 120/100, propellant 100/100, default credits 10000), placed more than 101 units from every belt center and >50 from gates/stations so asteroid belts still reach their target count. `chem_engine_s` gains the module stat `fuelUse: 0.002`; `ShipStats` derives `FuelUsePerUnit` (sum of `fuelUse` stats). The dock shows propellant automatically through the existing `trade` service (market entries come from the recipe outputs) — no new service in 4b.

**Consumption.** `Travel.Start` no longer charges credits; it deducts `Refuel.Consume(ship, distance)` from the tank, where `distance` is the sum of the leg lengths (legs lie within sectors, so gate jumps stay free) and the units are `distance × Stats.FuelUsePerUnit / efficiency` of the active fuel. `EconomyRules.FuelCostPerUnit` stays as data only. New `Travel` helpers: `EstimateDistance` (straight-line in-sector distance), `PlannedDistance` (planned legs incl. detours), `EstimateFuel`. Player flight does not go through `Travel.Start`, so the player tank is untouched in 4b (tanking service comes in 4c).

**NPC refueling** (`Simulation/Refuel.cs`, pure functions over the universe, deterministic ordering): `ActiveFuel` (on-board fuel with highest efficiency, else first allowed), `Consumption`, `Consume`, `CurrentStation` (dock-point match), `FuelStations`/`NearestFuelStation`, `BuyFuel`/`TankUp` (market price, books stock, station credits, ship credits into the tank — not the hold — and publishes `FuelBought`), `EmergencyBuy` (2× base price, money sink paid to no station, rounds the amount up so the next fuel station is truly reachable, publishes `EmergencyRefuel`), `FuelPrice`/`TripFuelCost`, and `PrepareTrip` → `Depart` / `FuelStop` / `Stuck`. `PrepareTrip` treats the tank as sufficient only if it covers the trip **plus a reserve** (`MinFuelReserveFraction` = 0.75 × capacity) — otherwise refueling demand would hit all at once when the starting tanks run dry and no ship could reach a refinery anymore. It tanks at the current station if it sells fuel; else flies to the nearest reachable fuel station as a `GoToOrder` (tank on arrival in `TraderSystem`/`MinerSystem.Arrive`, then the real order is re-picked; a pending sell/deliver leg is re-attached to the best buyer); else buys emergency fuel and then flies to the fuel station; `Stuck` (broke / no fuel station) leaves the ship idling so `FleetSystem` abandons it as before. Both AI systems call `PrepareTrip` before every `Travel.Start` (buy leg, sell leg, field, delivery, leftover delivery). No ship may keep a ghost reservation: `GoToOrder` never reserves stock and is always paired with a transit.

**Route scoring.** `TraderSystem` subtracts `Refuel.TripFuelCost` (consumption of ship→buy→sell × fuel price at the current/buy station, else the average over fuel stations, else base price) from `margin × units`.

**Events / persistence.** New `FuelBought` and `EmergencyRefuel` events (bus only, not persisted). No new save fields — the save stays v5 (`Ship.Fuel` was already hashed and persisted in 4a), so save→load→continue remains bit-identical.

**Balance tool.** New `tank`/`notk` columns (cumulative `FuelBought`/`EmergencyRefuel` counts, also in the CSV) and a summary line: tank buys + cost, emergency buys + cost, propellant's average price ratio over the last 25%.

**Calibration.** `fuelUse` 0.002 with tank 200: 0.005 made propellant scarce (2.5–4× base) and squeezed the fleet, 0.003 hit the 3.0 warning and miners collapsed; 0.002 keeps the 20000-tick run green. 20000-tick balance run (default seed): exit 0, "Preise im Zielbereich", 14 traders / 8 miners (unchanged), 20 station tank-ups (24857 Cr), 0 emergency buys, propellant ≈ 0.61× base in the tail, energy and hydrogen columns in range (0.5–1.7, no degeneration vs the powerplant). Money: the old flat fuel sink is gone; fuel payments now flow ship→refinery, so ship credits end lower (~22k vs ~62k before) and station credits higher (~99k vs ~49k) — no knob was changed, the shift is the intended flow to the refinery.

**Tests.** New `tests/SpaceSim.Tests/FuelEconomyTests.cs` (8 tests): consumption counts only in-sector legs (gate jumps free) and leaves credits untouched, model-less ships consume nothing; tank-up at the current station with exact stock/credits/cost bookkeeping; station without fuel → fuel stop as `GoToOrder` + tank on arrival; emergency buy (2× base, sink, amount = ceil to reach the next station, then fuel stop) and broke → `Stuck`; refinery produces propellant (H2/energy down, stock up) and sells to a ship with correct credits/stock; trader scoring subtracts fuel cost (huge `fuelUse` → no order; control case picks one); determinism (same seed → same hash, save→load→continue bit-identical); 20000-tick invariants (no negative or over-cap tank, no ship in transit past its arrival, no ghost `GoToOrder`, tracker consistent, player tank still 200). `FuelModelTests`/`ContentTests` were adjusted where 4b changed their assumptions (refineries now trade propellant, `Travel.Start` is no longer credit-flat, tanks are not full after a run). 273 tests green, `dotnet build` 0 warnings, Godot selftest OK.

**Known weaknesses.** At 40000 ticks propellant creeps toward 4× base (the hydrogen supply caps refinery output; the lifecycle would have to build more electrolysis — same risk class as noted in SCHIFFSSLOTS.md). On some non-default seeds the knife-edge food/water chain tips into the warning band; the default seed (the gate used by the balance tool) is green.
